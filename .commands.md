# 🚀 Comandos do Desenvolvedor

Atalhos para agilizar o workflow. O agente deve executar todas as ações ao receber um comando.

---

## `/v` — Atualizar Versão (Bump + Build + Deploy)

Executa o fluxo completo de release:
1. Bumpa a versão em TODOS os arquivos (package.json, main.ts, renderer, etc.)
2. Atualiza o CHANGELOG
3. Typecheck + Build + Gerar instalador
4. Deploy Vercel (disable protection → deploy → disable again)
5. Criar GitHub Release com o .exe
6. Publicar versão no servidor Vercel
7. Commit + Push

---

## `/v patch` — Versão PATCH (0.1.X → 0.1.X+1)

Para correções de bugs. Exemplo: 0.1.3 → 0.1.4

## `/v minor` — Versão MINOR (0.X.0 → 0.X+1.0)

Para novas funcionalidades. Exemplo: 0.1.0 → 0.2.0

## `/v major` — Versão MAJOR (X.0.0 → X+1.0.0)

Para mudanças quebradoras. Exemplo: 0.1.0 → 1.0.0

---

## `/d` — Deploy Vercel

Apenas deploy do servidor:
1. Disable protection
2. Deploy
3. Disable protection
4. Publish version on server

---

## `/b` — Build Apenas

Typecheck + Build + Gerar instalador (sem deploy)

---

## `/g` — Git Push

Commit + Push das alterações pendentes

---

## `/r` — Release GitHub

Criar release + upload do .exe

---

## `/t` — Testar Servidor

Verificar se o Vercel está online:
- Heartbeat
- Update Check
- Fetch Update

---

## `/i` — Instalador

Apenas gerar o instalador NSIS

---

## Regra de Ouro

**Toda vez que o agente fizer uma alteração de código:**
1. Sempre bumpar a versão (patch)
2. Sempre rebuildar
3. Sempre fazer commit + push

**Nunca esquecer de atualizar a versão!**
